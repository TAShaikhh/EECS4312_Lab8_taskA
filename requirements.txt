## 1. Problem Understanding - Describe the problem your system solves.
System purpose:
Recommend valid appointment slots inside a working day while respecting existing busy intervals, meeting duration, optional buffer time, and an optional candidate window.

Inputs to the system:
Working hours, busy intervals, meeting duration, maximum number of slots, optional buffer time, and optional candidate window.

Outputs produced by the system:
A chronologically ordered list of valid appointment slots, plus deterministic diagnostics for normalization actions and no-result outcomes when explanation support is requested.

Primary goal of the system:
Help users find valid appointment slots quickly and reliably while providing predictable behavior for Jane and explicit explanations for Mo.
---
## 2. Assumptions - List assumptions about the environment, users, or inputs.
A1:
All input datetimes refer to the same calendar day.

A2:
Working hours form a non-wrapping interval where start is strictly earlier than end.

A3:
Meeting duration and buffer time are measured in whole minutes.

A4:
Users want the earliest valid slots first unless a stricter candidate window is supplied.

A5:
Busy intervals may be unsorted, overlapping, adjacent, reversed, or zero-length.

A6:
If explanation support is requested, users prefer deterministic reason codes over vague narrative messages.
---
## 3. Functional Requirements - Describe the main behaviors the system must perform.
FR1:
The system shall return appointment slots only within the intersection of working hours and the candidate window, if a candidate window is provided.

FR2:
The system shall normalize busy intervals by swapping reversed intervals, discarding zero-length intervals, clipping intervals to the effective window, and merging overlapping or adjacent intervals.

FR3:
The system shall return slots in deterministic earliest-first chronological order and limit the output to the requested maximum number of slots.

FR4:
The system shall ensure that every returned slot is exactly the requested meeting duration and does not overlap any busy interval or violate required buffer distance.

FR5:
The system shall provide deterministic explanation data describing normalization actions applied to busy intervals.

FR6:
The system shall provide a deterministic no-result reason code when no valid slots can be returned after input validation succeeds.

## 5. Acceptance Criteria - Acceptance criteria define how system behavior will be verified.
AC1:
Given working hours 09:00-17:00, no busy intervals, meeting duration 30, and num_slots 2
When the scheduling function is executed
Then the system returns [(09:00, 09:30), (09:30, 10:00)] in chronological order.

AC2:
Given a busy interval 10:00-11:00 and buffer time 15 minutes
When the scheduling function is executed
Then no returned slot ends after 09:45 or starts before 11:15.

AC3:
Given overlapping or adjacent busy intervals
When the scheduling function is executed
Then the system merges them before calculating free gaps and does not return a slot inside the merged blocked interval.

AC4:
Given a candidate window that lies inside working hours
When the scheduling function is executed
Then every returned slot starts and ends inside the effective window.

AC5:
Given identical inputs in repeated executions
When the scheduling function is executed twice
Then both executions return the same ordered list of slots.

AC6:
Given a candidate window outside working hours
When the diagnostics function is executed
Then the system returns no slots and the no-result reason code is candidate_window_outside_working_hours.

AC7:
Given an effective window shorter than the meeting duration
When the diagnostics function is executed
Then the system returns no slots and the no-result reason code is duration_exceeds_effective_window.

AC8:
Given reversed, zero-length, or partially out-of-range busy intervals
When the diagnostics function is executed
Then the system records deterministic processing notes describing swap, discard, clip, or merge actions.

## 6. Edge Cases - Describe unusual or boundary situations the system must handle.
EC1:
Candidate window is entirely outside working hours.
Expected system behavior:
Return no slots and report candidate_window_outside_working_hours.

EC2:
Meeting duration is longer than the effective scheduling window.
Expected system behavior:
Return no slots and report duration_exceeds_effective_window.

EC3:
Buffers eliminate an otherwise valid free gap between busy intervals.
Expected system behavior:
Return no slots in that gap and report no_feasible_gap_after_conflicts_and_buffers if no other valid slots exist.

EC4:
Busy intervals are unsorted, reversed, overlapping, adjacent, or zero-length.
Expected system behavior:
Normalize them deterministically before slot generation and report the normalization actions.

EC5:
Busy intervals extend outside the effective window.
Expected system behavior:
Clip intervals to the effective window and discard intervals that fall completely outside it.
